<en-sus-palabras>
Las historias de usuario se escriben después de haber realizado el prototipo. El prototipo no se arma a partir de historias que ya existían: se arma con las capacidades que salieron del destilado y que el desarrollador escogió. Las historias se formalizan ya con lo que el cliente corrigió al ver el prototipo funcionando; después se seleccionan, se revisa que estén completas, y con ellas entra el flujo de construcción.
</en-sus-palabras>

<de-donde-salio>
El experto trajo la duda él mismo: si las historias de usuario se generan antes o después del prototipo, o si los desarrolladores trabajan sin ellas, y por qué para el software productivo sí quedarían historias y para el prototipo no. Se le devolvió una lectura —una historia es un compromiso y un prototipo es una pregunta, y comprometerse antes de preguntar es lo que hace que las historias se reescriban— con la petición expresa de que la corrigiera. Al preguntárselo de nuevo, contestó que después del prototipo.
</de-donde-salio>
